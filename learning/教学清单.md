## 一、教学规则（运行协议）

### 1.1 每次教学启动：输出什么文件

每次启动一次教学（新的一天 / 新的一个学习时段），**先创建/更新以下文件**：

| 文件 | 类型 | 内容 | 模板 |
|---|---|---|---|
| `learning/教学进度-YYYYMMDD.md` | 输出（每日新建） | 当日计划、实际完成、卡点、明日计划 | 见 1.1.1 |
| `learning/产出/<编号>-知识卡.md` | 输出（每完成一个清单项新建） | 该知识点的"一句话结论 + 关键机制 + 与 AgentScope 对照 + 源码/链接" | 见 1.1.2 |
| `learning/教学清单.md`（本文件） | 修改 | 勾选状态、日期头更新 | — |

**1.1.1 进度日志模板**（每日新建 `learning/教学进度-YYYYMMDD.md`）：

```markdown
# 教学进度 2026-09-24
## 今日目标（来自时间表）
- [ ]
## 实际完成（勾选清单项 + 一句话收获）
- [x] A-03 入口与配置 —— 掌握了 4 份 config 的分工
## 卡点 / 未完成项（写清原因）
- 
## 明日计划
- 
## 当日自检（对照达标考核体系）
- [ ] 能复述今日学过的核心机制（3 句话内）
- [ ] 产出知识卡已写入 learning/产出/
- [ ] 清单状态已同步
```

**1.1.2 知识卡模板**（每完成一个清单项，输出到 `learning/产出/<编号>-知识卡.md`）：

```markdown
# <编号> <标题>
- 一句话结论：
- 核心机制（3-5 条，每条一句话）：
- 与 AgentScope 的对照（迁移点）：
- 关键源码/文档位置：
- 一图流（可画，不强制）：
```

### 1.2 每次教学启动：修改什么文件

| 动作 | 文件 | 修改内容 |
|---|---|---|
| 教学启动 | `learning/教学清单.md` | ① 更新文件头的"当前日期/阶段"行；② 将昨日遗留 `[~]` 项复查 |
| 开始一项 | `learning/教学清单.md` | 该项 `[ ]` → `[~]` |
| 完成一项 | `learning/教学清单.md` | 该项 `[~]` → `[x]`（**必须先满足验收标准**，见 1.3） |
| 完成一项 | `learning/产出/<编号>-知识卡.md` | 新建知识卡（若还没写） |
| 结束一天 | `learning/教学进度-YYYYMMDD.md` | 补当日自检、卡点、明日计划 |

> 铁律：**清单是唯一状态源**。口头说的"学会了"不算，清单上 `[x]` + 知识卡存在才算。

### 1.3 状态标记规则（可标记语义）

| 标记 | 含义 | 进入条件 | 离开条件 |
|---|---|---|---|
| `- [ ]` | 未开始 | 默认状态 | 开始动手 |
| `- [~]` | 进行中 | 已开始但未达验收 | 完成或放弃 |
| `- [x]` | 已完成 | **验收标准全部满足** | 原则上不回退；若发现理解有误，改回 `[~]` 并重学 |
| `- [-]` | 跳过/不适用 | 经判断该项不影响目标 | 需在进度日志写明原因 |

**验收标准的三级口径**（每一项的"验收"字段都按此口径写）：
- **能讲**：不看资料，用 3 句话讲清"这是什么、解决什么问题、核心机制是什么"
- **能画**：能画出该项的架构/调用链/状态图（手绘或 draw.io 均可，拍照存进知识卡）
- **能做**：能运行/复现/写出最小示例，输出物存在

只有三项全满足才允许 `[x]`。

### 1.4 节奏规则（时间盒）

- 每个清单项右上角标注了建议时长，**超时 1.5 倍仍未完成 → 降级为"概念级"继续**（在进度日志标注"概念级"），不阻塞后续项。
- 每天结束前 15 分钟固定做"当日自检"（见进度日志模板）。
- 每天最多 3 个卡点记录；同一卡点连续出现 2 天 → 必须换学习通道（示例→源码→官方文档→问人）。

## 二、清单维护规则

### 2.1 维护者与时机

- **维护者**：学习者本人（AI 可在每次教学启动时协助执行，但以清单上的真实勾选为准）。
- **维护时机**：每次教学启动时、每个清单项状态变化时、每天结束时。
- 允许批量勾选，但**必须**逐项满足验收；禁止"整块标完成"。

### 2.2 条目生命周期

```
[ ] 未开始 ──开始──▶ [~] 进行中 ──验收通过──▶ [x] 已完成
   ▲                     │
   └──── 放弃/不适用 ────┴──▶ [-] 跳过
[x] 已完成 ──发现理解有误──▶ [~]（回退重学，不直接改回 [x]）
```

### 2.3 变更规则

- **增条目**：任何时候可加，编号续排（如 A-13、C-19），并注明加入日期。
- **删条目**：不允许删除，只能标 `[-]`（保留审计痕迹）。
- **改验收**：允许放宽/收紧，但必须**同步修改该项验收字段**并在进度日志记录原因。
- **回滚**：`[x]` → `[~]` 需在进度日志写一句"为什么回滚"。

### 2.4 冲突处理

- 清单与时间表冲突 → 以清单为准（时间表是建议，清单是事实）。
- 清单与学习规划文档冲突 → 以清单为准（清单是最新意图）。
- 连续两次把同一项从 `[x]` 回退 → 该项标记为"薄弱项"，加入 Day 3 综合测验复考名单。

## 五、达标考核体系（如何确保教学结果达标）

**三层保障**：

1. **过程层（每天）**：验收三级口径（能讲/能画/能做）内嵌每个清单项；当日自检 + 知识卡产出强制。
2. **结果层（Day 3）**：D-01 抽查（≥80% 通过）+ D-02 对比矩阵（≥15 框架）+ D-03 迁移演示。
3. **审计层（随时）**：清单是唯一状态源；`[x]` 必须能指到对应知识卡；任何"感觉会了"都须落到三个文件之一（清单/进度/知识卡）。

**达标判定**：
- **Day 1 达标** = A-01~A-12 中 ≥10 项 `[x]`，且 A-04（主循环）、A-08（中间件）、A-09（服务层）三项必须 `[x]`。
- **Day 3 达标** = B 模块 ≥8 项、C 模块 ≥15 项 `[x]`，D-01 抽查 ≥80%，D-02/D-03 交付物存在且自洽。
- **未达标处理**：标 `[-]`/回退的项在进度日志留痕；Day 3 结束后按薄弱清单定向补漏（每项 ≤1h）。

## 六、诚实边界声明

**可达目标（本清单的设计基准）**：
- Day 1：AgentScope **核心机制级**掌握（主循环/消息事件/模型工具/中间件权限/服务层主线）+ 全部扩展模块**概念级**认知。
- Day 3：市面 80% harness 的**设计与底层原理级**掌握（六元组/五维统一模型下的机制与取舍）。

**不可达目标（请勿误判为失败）**：
- 一天内精通 478 个源码文件的每一个细节；
- 三天内达到任一框架的 API/工程精通级（那是每个框架数周的事）；
- "所有额外扩展知识"中的深度细节（如某框架的某适配器源码）。

**设计对冲**：清单用"概念级"与"机制级"显式分级，超时即降级继续，保证三天内**跑完全程**而非停在第一个卡点上——全程跑完的 80%，远大于卡死在细节里的 20%。
