# C-18 补充与平台面（Agno / DSPy / MetaGPT / 低代码）

- **一句话结论**：除了主流框架，harness 光谱上还有几类重要存在——**Agno**（agent platform，四模式团队）、**DSPy**（提示编程/编译优化层）、**MetaGPT**（SOP 多智能体）、**低代码平台**（Dify/Coze/Flowise/n8n，部署形态）；理解"harness / 框架 / 平台"三类边界是全覆盖的最后一块拼图。

## 四类补充

### Agno（agent platform）
- 定位：生产级 agent 平台；Native **Teams 四模式**（Coordination/Route/Workflow/Collaborate）、Session + Vector memory、用户确认流（user confirmation flows）
- 迁移点：Teams 四模式 ≈ AgentScope 的四种编排（自由/路由/流水线/协作）——"编排模式穷举"思路一致

### DSPy（提示编程/编译）
- 定位：不是运行时 harness，而是 **"prompt 编程 + 优化"层**——用声明式模块（Signature/Module）编译出最优 prompt 与思维链，可套在任何 harness 之上
- 迁移点：DSPy 优化的是 C（上下文组装）与提示质量——与 AgentScope 的 `_prepare_model_input`/注入配置是不同抽象层

### MetaGPT（SOP 多智能体）
- 定位：研究向，把"软件开发流程"（产品经理/架构师/工程师…）编码为 **SOP（Standard Operating Procedures）** 驱动多智能体协作
- 迁移点：SOP 编排 ≈ AgentScope 的 SOPEngine——"结构化步骤 + 角色 + 验证"同一思路，MetaGPT 偏领域（软件工程）

### 低代码/平台（Dify / Coze / Flowise / n8n）
- 定位：**部署形态层**——把 harness 能力封装成可视化编排与托管服务（拖拽节点、知识库、工作流）
- 与框架的关系：平台内部往往跑着一个/多个 harness（Coze 类平台内置 ReAct 循环）；适合业务人员，不适合深入控制
- 迁移点：平台=harness 的"消费级前端"，框架=harness 的"工程级接口"

## 三类边界（能讲即全覆盖）

```
Agent Harness（运行时本体）: AgentScope / LangGraph / OpenAI SDK / dsh / smolagents ...
Agent Framework（构建工具）: DSPy / LlamaIndex Workflows / Vercel AI SDK（偏 UI 管道）...
Agent Platform（部署形态）: Agno / Dify / Coze / Flowise / n8n / Microsoft Hosted Agents ...
```
边界不是严格的——**理解"同一问题的不同答案 + 不同抽象层"**即可（B 模块的六元组/五维坐标系仍然适用）。
