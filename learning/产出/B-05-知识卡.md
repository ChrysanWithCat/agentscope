# B-05 Context 管理

- **一句话结论**：Context Management 是 harness 性能的"隐形瓶颈"——窗口有限而任务无限，核心策略是**压缩（compaction）、卸载（offload）、检索注入（retrieval）、缓存（caching）**四件套；生产 harness 几乎都做"文件持久/混合/层级"而非纯内存。

## 四件套策略

| 策略 | 机制 | 适用 | 代表实现 |
|---|---|---|---|
| **Compaction 压缩** | 用 LLM 把旧历史生成结构化摘要，替换原上下文 | 长对话、长任务 | AgentScope `compress_context` + SummarySchema（五段式）；LangGraph 的 summarize 节点 |
| **Offload 卸载** | 把大块内容（工具结果/图片）移到外部存储，留提示/路径 | 超大工具结果、多模态 | AgentScope `Offloader` + workspace；OpenAI Codex 的文件句柄 |
| **Retrieval 注入** | RAG：检索相关知识拼进上下文 | 知识密集型 | AgentScope `RAGMiddleware`、LlamaIndex |
| **Caching 缓存** | prompt 缓存（前缀命中） | 重复前缀、多轮 | OpenAI/Anthropic prompt caching、AgentScope Usage.cache_input_tokens |

## 关键设计决策（五维的 Context 维度）

1. **存储后端**：内存（原型）→ 文件持久（生产常见）→ 分层（短期+长期）
2. **压缩触发**：按 token 比例（AgentScope trigger_ratio=0.8）？按轮次？模型主动（压缩工具）？
3. **压缩内容**：什么值得留（用户意图/约束/承诺/关键决策）vs 什么可丢（中间过程）
4. **持久化范围**：每会话？跨会话（长期记忆）？
5. **Token 感知**：是否把上下文占用注入给模型（AgentScope `_inject_runtime_state` + buffer 提示"压缩临近"）

## 压缩质量的核心（AgentScope 的 SummarySchema）

压缩摘要不是"总结"，而是**可恢复的工作状态**，五段缺一不可：
`task_overview`（目标与成功标准）→ `current_state`（已完成）→ `important_discoveries`（关键发现/决策/错误）→ `next_steps`（下一步+阻塞）→ `context_to_preserve`（用户偏好/承诺/领域细节）
另有两个工程要点：**自包含性**（相对时间/代词必须解析为绝对形式）、**in-flight 工作标记**（后台任务及其归属/状态）——压缩后上下文被替换，一切引用必须自洽。

## 与 AgentScope 的对照（迁移点）

- ContextConfig：trigger_ratio / reserve_ratio / context_buffer_ratio / compression_prompt / summary_template / tool_result_limit / max_image_num / compression_tool_enabled
- 运行时注入（InjectionConfig）：时间、任务状态、上下文占用——"让模型感知自己在长任务中的位置"
- 对比：LangGraph 把 context 归入 state（checkpoint 的一部分）；OpenAI Agents SDK 用 session 隔离 + 自动摘要。**三家的压缩都是"摘要替换"，差别在触发与存储**。
