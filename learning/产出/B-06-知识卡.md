# B-06 Tool 系统设计

- **一句话结论**：Tool System 是 harness 的 I_act 维度——把模型输出变成可执行操作；核心设计面是**注册方式、schema 质量、执行路径、协议集成（MCP/A2A）、并发与安全**；其中"工具描述的 token 质量"是 agent 成功率的头号杠杆。

## 关键设计面

| 设计面 | 问题 | 选项与权衡 |
|---|---|---|
| **注册方式** | 工具如何进入 harness | 显式注册表（AgentScope Toolkit）/ 装饰器 / 插件 / 全自动发现 |
| **Schema 质量** | 描述与参数定义怎么写 | 好描述=少幻觉调用；坏 schema=工具调用 JSON 频繁解析失败（`json_repair`、StructuredOutputError） |
| **执行路径** | 工具在哪运行 | 进程内（快/不安全）/ 沙箱（隔离）/ 远程（容器/K8s/云） |
| **协议集成** | 工具来自哪里 | 本地函数 / **MCP**（通用工具协议）/ **A2A**（智能体间协议） |
| **并发控制** | 同一工具的并行 | `is_concurrency_safe`（读可并发、写需串行）；批处理（顺序/并发） |
| **结果治理** | 结果怎么回模型 | 截断（token 上限）、压缩、卸载、错误结构化回传 |

## 工具描述质量为何是头号杠杆

- 模型靠 **name + description + 参数 schema** 决定何时调用、传什么参。
- 描述含糊 → 不该调用时调用（浪费轮次）或该调用时不调用（任务失败）。
- 参数 schema 不严 → JSON 生成失败率上升 → 需要 `json_repair` 或重试（AgentScope 依赖 `json_repair[schema]`）。
- **生产实践**：工具数量不是越多越好（模型选择困难），按需分组（AgentScope `ToolGroup` 可整体启用/停用）。

## MCP 与 A2A 的定位差异（2026 关键协议）

- **MCP**（Model Context Protocol，工具协议）：把"工具/资源/提示"标准化，harness 经 MCP Client 连接任意工具服务器——`StdioMCPConfig`（本地进程）/ `HttpMCPConfig`（远程）。
- **A2A**（Agent-to-Agent，智能体协议）：把"智能体能力"标准化，让不同厂商的 agent 互操作——AgentScope `A2AAgent`、Microsoft Agent Framework 原生 A2A。
- 一句话：**MCP 管"智能体怎么用工具"，A2A 管"智能体怎么找/对话其他智能体"**。

## 与 AgentScope 的对照（迁移点）

- Toolkit（注册表）→ FunctionTool / MCPTool / Skill 三类适配 → ToolChoice（约束）→ `ToolGroup`（分组）
- 失败处理：`ToolInterruptedError` / `ToolNotFoundError` / `ToolJSONDecodeError` / `ToolGroupInactiveError`（异常分级）
- 对比：OpenAI Agents SDK 用 `@function_tool` 装饰器 + guardrails 校验参数；smolagents 放弃结构化 schema，直接让模型写代码（CodeAct）。
