# C-09 Google ADK（Agent Development Kit）

- **一句话结论**：Google ADK 是 Google 官方的 agent 开发套件（Python + JS），以 **Agent/Runner + 会话（Session）+ 分层记忆（Memory）** 为核心，内置 **MCP/A2A 双协议** 与回调（callbacks）机制——是"云原生 + 双协议"路线的代表。

## 六元组速览

| 维度 | 答案 |
|---|---|
| L 循环 | Runner 驱动 agent 循环；callback（before/after model call、tool call 等）做横切 |
| I_act | 工具（function tools）+ **MCP** + **A2A** 双协议；Code execution |
| C 上下文 | 指令（instructions）+ 会话内历史；**Memory 分层**（长期记忆模块） |
| S 状态 | **Session 是一等公民**：会话状态持久化（含用户状态），可恢复 |
| V 验证 | callback 观测；A2A 卡片 |
| 多智能体 | agent 间 A2A 互通；多 agent 编排 |

## 核心机制（3 条）

1. **Session 即状态**：ADK 把 session 作为核心抽象（session 内保存对话+变量+状态），可持久化/恢复——与 AgentScope 服务层的 Session 模型同思路。
2. **双协议默认**：MCP（工具）+ A2A（智能体）都内建——Google 押注"开放协议生态"，与微软 Agent Framework 路线一致。
3. **Callback 横切**：生命周期回调（on_before_model_call / on_after_tool_call 等）≈ AgentScope 中间件钩子（7 钩子点），命名与挂点略有差异。

## 与 AgentScope 对照

- 会话状态：ADK Session vs AgentScope AgentState+Storage（都做会话级持久化）
- 横切：ADK callbacks vs AgentScope middlewares（机制同构：生命周期钩子链）
- 协议：ADK MCP+A2A 双内建；AgentScope MCPTool 适配 + A2AAgent
- 定位：ADK 云原生（Google Cloud 生态）；AgentScope 自托管服务（FastAPI）
