# A-06 模型、凭据、格式化三层

- **一句话结论**：AgentScope 用 **Credential（凭据）→ Model（模型）→ Formatter（格式）** 三层把"厂商差异"彻底隔离——上层（Agent 主循环）只面对统一的 `ChatModelBase`，厂商差异被压到最底层。

## 三层架构

```
Agent 主循环 ──▶ ChatModelBase（统一接口）          ← 上层只见这一层
                    ├─ 内部组装请求 → FormatterBase   ← 把统一消息转成厂商格式
                    └─ 调用厂商 SDK ← CredentialBase  ← 各家 API Key 封装
```

## ① 凭据层（`credential/`）
- `CredentialBase` 抽象 + 9 家实现：Anthropic / DashScope / DeepSeek / Gemini / Moonshot / Ollama / OpenAI / Volcengine / XAI / TypeSafe
- `CredentialFactory`：按模型类型注册/查找凭据——服务层动态创建模型时靠它
- 设计点：凭据与模型解耦，同一模型可换凭据、同一凭据可服务多模型

## ② 模型层（`model/`）
- `ChatModelBase`：统一异步接口（`__call__`/`stream`），内部管理重试
- `ModelCard`：模型元信息（上下文长度等）；`ChatUsage`：token 统计（input/output/cache）
- `ChatResponse`：统一回复对象（role/name/content/blocks/usage/finished_reason）
- `StructuredResponse`：结构化输出（pydantic schema 校验后）
- `FinishedReason`：STOP / LENGTH / CONTENT_FILTER / TOOL_CALLS / INTERRUPTED / ERROR
- 10 家实现：`OpenAIChatModel`（chat 兼容）、`OpenAIResponseModel`（responses API）、`AnthropicChatModel`、`DashScopeChatModel`、`DeepSeekChatModel`、`GeminiChatModel`、`MoonshotChatModel`、`OllamaChatModel`、`VolcengineChatModel`、`XAIChatModel`

## ③ 格式化层（`formatter/`）
- `FormatterBase` + 每家 **ChatFormatter**（单 Agent）与 **MultiAgentFormatter**（多 Agent 通信格式，20 个类）
- 职责：统一消息（Msg/ContentBlock）→ 厂商 API 的 message 结构；反向解析厂商响应 → ChatResponse
- 关键点：**多 Agent 场景各家格式不同**（如 DashScope 的 messages 数组 vs Anthropic 的 system+messages），所以每家有双套 formatter

## 设计哲学（迁移点）

对应 harness 的 **I_act（动作接口）适配层**：模型层不感知工具定义差异，formatter 负责把 ToolCallBlock 序列化成各家 function-calling 格式。新增一家厂商 = 写 Credential + ChatModel + Formatter 三件套（对照 `model/_deepseek/` 全套模式）。
