# B-01 harness 术语与范式

- **一句话结论**：**Agent Harness = 包裹在 LLM 周围、把概率模型变成可靠软件代理的整套基础设施**（编排循环、工具、记忆、上下文管理、状态持久化、错误处理、安全护栏）；2026 年该术语被正式化（Anthropic 称 Claude Code SDK 为 "the Agent Harness"、OpenAI Codex 视 agent 与 harness 同义、DeepSeek 提出 "Agent = Model + Harness"），行业共识是：**模型权重之外的 harness 工程，决定 agent 性能的 70%**。

## 核心机制（5 条）

1. **术语正式化**：2026 年初起，"harness" 成为行业标准术语；Anthropic Claude Code 文档明确 SDK 是 "agent harness"，Microsoft Agent Framework 发布同名概念（BUILD 2026），DeepSeek Harness（dsh）以 "Everything is a Plugin" 开源。
2. **基本等式**：`Agent = Model + Harness`——模型是推理引擎，harness 是控制中心（环境交互、工具契约、上下文流转、沙箱）。
3. **性能共识**：一个 harness 工程良好的中等模型，胜过 harness 粗糙的大模型；瓶颈已从模型权重转移到 harness（基础设施是 agentic performance 的主决定因素）。
4. **harness 的组成**（业界列举）：orchestration loop（编排循环）、tool integration（工具）、memory（记忆）、context management（上下文管理）、state persistence（状态持久化）、error handling（错误处理）、safety guardrails（安全护栏）。
5. **统一的抽象**（综述形式化）：H = ⟨I_obs, C, L, I_act, S, V⟩（观测输入 / 上下文组装 / 控制循环 / 动作接口 / 状态持久化 / 验证恢复）。

## 为什么"harness"重要（迁移点）

- 把注意力从"换更大模型"转向"改造运行基础设施"：同样的模型，改循环停止条件、工具描述质量、上下文策略，性能差异巨大。
- 学习任何 agent 产品（Claude Code、OpenAI Codex、DeepSeek Harness、OpenClaw…）时，解剖的是 harness 而非模型；理解 harness 设计 = 理解 80% 的 agent 生态。
