# B-02 六元组模型 H=⟨I_obs, C, L, I_act, S, V⟩

- **一句话结论**：2026 年综述（arXiv 2606.20683）把 harness 形式化为六元组 **H = ⟨I_obs, C, L, I_act, S, V⟩**——六个子系统回答"哪些观察进模型、上下文怎么组装、循环怎么推进、动作怎么执行、状态怎么持久化、失败怎么检测恢复"；这是横跨所有框架的统一坐标系。

## 六元组详解

| 元组 | 全称 | 职责 | 设计问题 |
|---|---|---|---|
| **I_obs** | Observation Input | 环境反馈如何被观察到并送入模型 | 工具结果、传感器、用户输入的采集与格式化 |
| **C** | Context Assembly | 上下文如何组装 | 历史窗口、检索注入、系统提示、压缩/卸载、缓存 |
| **L** | Control Loop | 循环如何推进 | 步骤调度、停止条件、重试、反思、委派、交接、多智能体协调、模型路由 |
| **I_act** | Action Interface | 模型输出如何变成可执行操作 | 函数调用、MCP 工具、shell/代码执行、浏览器动作、文件操作 |
| **S** | State Persistence | 状态与产物如何保存 | 会话状态、checkpoint、任务状态、工件持久化 |
| **V** | Verification | 失败如何检测/治理/恢复 | 停止判定、重试策略、护栏、审计、恢复 |

## 关键洞察（迁移点）

1. **V 是被低估的第六维**：生产 harness 与原型的分水岭——"什么时候停、失败怎么办"（如循环永不停止 vs 提前放弃，都是 V 的失败模式）。
2. **六元组不是独立模块，而是交叉子系统**：L 决定何时读 C、何时触发 I_act；V 观察 L 与 I_act 的结果。
3. **学习迁移法**：对任意框架/产品，依次问这 6 个问题，答案即其设计指纹。AgentScope 映射见 A-11。

## 生产循环的最小伪代码（survey 提炼）

```
Assemble（组装上下文）→ Model call（推理）→ Gate（风险评分/审批）
→ Execute（沙箱内执行）→ Observe（追加到 trace）
→ loop until: done · budget exhausted · evaluator veto · abort
```
五条伪代码，每条箭头后面都是一个子系统——"每行都藏着一套工程"。
