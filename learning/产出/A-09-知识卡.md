# A-09 服务层主线（把 Agent 变成应用）

- **一句话结论**：`create_app(storage, message_bus, workspace_manager, ...)` 组装出一个 FastAPI 应用：HTTP 路由（`_router`）→ 业务服务（`_service`，核心是 ChatService）→ 驱动 SDK 的 Agent → 结果经 AGUI 协议投影回前端；持久化、渠道、调度、团队都是这条主线的周边件。

## create_app 组装（`app/_app.py:78`）

**三必需件**：
| 组件 | 职责 |
|---|---|
| `storage: StorageBase` | 持久化（Redis / SQL），生命周期随 app |
| `message_bus: MessageBus` | 跨会话投递/唤醒（InMemory / Redis）——与存储解耦 |
| `workspace_manager: WorkspaceManagerBase` | 每个会话/Agent 分配工作空间（沙箱） |

**可选件**：knowledge_base_manager（RAG 服务）、mcp_hubs/skill_hubs（资源 Hub）、channels（IM 渠道）、custom_subagent_templates（团队子代理模板）、extra_agent_middlewares/tools、enable_scheduler/channel_worker/index_worker 开关。

## 一次聊天请求的链路

```
POST /chat（_router/_chat.py）
  → ChatService.run（_service/_chat.py）
      ├─ 找/建会话（session）
      ├─ 构建 Agent 实例（按 user×agent×session，挂 app 层中间件）
      ├─ Agent.reply_stream(...)      ← 进入 SDK 主循环（路径 A）
      ├─ _persist()                   消息/状态写存储
      └─ _project_event()             AgentEvent → AGUI 协议 → WebSocket/SSE/渠道
```

## 服务层四大板块

1. **存储（`app/storage/`）**：`RedisStorage`、`SQLStorage`（SQLAlchemy async + Alembic 迁移）；数据模型 10+：Agent/Channel/Credential/KnowledgeBase/KnowledgeDocument/MCP/Schedule/Session/Skill/Team/User
2. **调度与后台（`app/_manager/`）**：`SchedulerManager`（cron 定时唤醒 Agent）、`BackgroundTaskManager`（长任务卸载）、`WakeupDispatcher`（总线唤醒）、`CancelDispatcher`、`ChatRunRegistry`
3. **渠道（`app/channel/`）**：`ChannelBase` 抽象 + 飞书/Discord/钉钉实现 + 渠道工具（发消息/文件/图片）+ 消息路由/网关/worker 长连接
4. **团队（`app/_tool/`）**：`TeamCreate/TeamSay/TeamDelete`、`AgentCreate/AgentInvite` —— Leader 派生 Worker 编排

**服务端中间件**（`app/middleware/`）：`InboxMiddleware`（收件箱）、`StateChangeMiddleware`、`TeamMemberMiddleware`、`ToolOffloadMiddleware`（后台工具）、AGUI 协议投影。

## 关键设计（迁移点）

- **服务层不重复实现智能体逻辑**——只是"编排实例 + 跑 SDK 的 Agent + 持久化 + 转发事件"，这是"harness 平台化"的典型形态（对比 Microsoft Agent Framework 的 hosted agents）
- `message_bus` 与 `storage` 解耦：持久化（SQL）与传输（Redis）可不同——对应多进程部署的分布式 harness
