# C-13 Vercel AI SDK

- **一句话结论**：Vercel AI SDK 是"**UI 优先**"的 TS harness——把 LLM 流式输出、工具调用、agent 会话直接接到 React/Next.js 组件（`useChat`/`useAgent`），核心定位是"前端与 LLM 之间的管道"，而非完整运行时。

## 六元组速览

| 维度 | 答案 |
|---|---|
| L 循环 | 轻量 agent 循环（SDK 提供工具循环）+ 主要靠前端驱动 |
| I_act | 工具定义（TS 函数）+ `streamText`/`generateText` 工具调用流 |
| C 上下文 | 消息数组直通（messages）；前端管理历史 |
| S 状态 | 会话由前端/后端协商（无强持久化保证） |
| V 验证 | 流式协议（数据流 + 工具调用流）；SDK 层校验 |
| 多智能体 | 多 agent 支持（2026 扩展，UI 编排） |

## 核心机制（3 条）

1. **流式管道是核心**：`streamText` 把 token/工具调用/错误作为统一数据流推向 UI——"**LLM 到浏览器**"的最后一公里（AgentScope 用事件流+AGUI 协议，同一目标）。
2. **前端集成是卖点**：`useChat` hook 一行接入聊天 UI（loading/error/重试内建）——适合"聊天产品"而非"后台 agent 服务"。
3. **协议适配**：支持多家模型（OpenAI/Anthropic/Google…）+ 自定义 provider——模型无关的 UI 层。

## 与 AgentScope 对照

- 事件流：Vercel 的 streamText 流 vs AgentScope 的 AgentEvent 流——都解决"流式到前端"，协议不同
- 定位：Vercel 前端管道（薄）；AgentScope 完整运行时（厚）
- 生态：Vercel 与 Next.js 深度绑定；AgentScope 自带 Web UI（examples/web_ui）但自托管
