# A-08 中间件与权限引擎

- **一句话结论**：**中间件**在 7 个钩子点以"洋葱链"方式包裹主循环，**权限引擎**在工具执行前做细粒度决策（ALLOW/REJECT/REQUIRE_CONFIRM）——一个是"横切扩展"、一个是"安全闸门"，两者都由 Agent 构造时注入。

## ① 中间件（`middleware/_base.py`）

**7 个钩子点**（`MiddlewareBase` 的 7 个方法，`is_implemented` 按实现分流）：

| 钩子 | 时机 | 典型用途 |
|---|---|---|
| `on_reply` | 整个 reply 最外层 | 日志、审计、吞 ReplyEndEvent 强制多轮 |
| `on_reasoning` | 每次推理前 | 改写请求、注入上下文 |
| `on_acting` | 每次行动前 | 拦截/改写工具调用 |
| `on_check_permission` | 权限检查时 | 附加审批策略 |
| `on_model_call` | 模型调用时 | 缓存、路由、观测 |
| `on_compress_context` | 上下文压缩时 | 自定义压缩策略 |
| `on_system_prompt` | 取系统提示时 | 动态拼接提示 |

**执行机制**：Agent 构造时把中间件按钩子分流存桶（`_reasoning_middlewares` 等）；执行时用 `execute_chain` 把同钩子中间件串成链，每个中间件可 `await next_handler()` 放行或提前返回（甚至吞掉结束事件）。

**内置中间件**（`middleware/__init__.py`）：
- `RAGMiddleware`：检索注入知识
- `ReplyBudgetControlMiddleware`：回复预算控制
- `TracingMiddleware`：OpenTelemetry 追踪
- `TTSMiddleware`：语音合成
- `ModelRouterMiddleware` + `ChatModelCandidate`：按回复选模型/回退
- 记忆：`AgenticMemoryMiddleware` / `Mem0Middleware` / `ReMeMiddleware`（三种后端，统一记忆协议）

## ② 权限引擎（`permission/`）

- `PermissionEngine`：决策入口（工具执行前调用）
- `PermissionRule`：规则对象（匹配工具/资源 → 决策）
- `PermissionDecision`：ALLOW / REJECT / REQUIRE_CONFIRM（可带提示消息）
- `PermissionMode`：如 `AGENT`（自主）与 bypass 模式
- `PermissionContext`：会话级权限上下文（含 `AdditionalWorkingDirectory` 额外工作目录授权）
- `PermissionBehavior`：决策行为枚举

**HITL 确认流**：
```
工具调用 → PermissionEngine → REQUIRE_CONFIRM
  → 发 RequireUserConfirmEvent（暂停循环，Exit 但回复未结束）
  → 用户确认 → UserConfirmResultEvent 恢复 → _reply_impl 从事件恢复执行
```

## 与 harness 通用设计的对应（迁移点）

- 中间件 = 五维架构的 **Orchestration 控制流扩展** + 可观测性（对应 Microsoft Agent Framework 的 middleware、LangGraph 的 pre/post model hooks）
- 权限 = 五维架构的 **Safety Mechanisms**（审批流 + 隔离）；对比 OpenAI Agents SDK 的 guardrails、CrewAI 的 human approval
