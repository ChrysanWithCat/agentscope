# C-17 应用型 harness 解剖：Claude Code / OpenAI Codex / Aider

- **一句话结论**：arXiv 2609.00006 对 11 个 coding agent 系统做源码级解剖，揭示"**编码 agent = 一组子系统的不同形态**"：Orchestration（编排）、Context、Tool、Safety、Extensibility 等——Claude Code（递归组合）、OpenAI Codex（插件市场）、Aider（刻意单代理）代表光谱两端。

## 核心机制（子系统最小↔最大形态，arXiv 2609.00006）

| 子系统 | 角色 | 最小形态 | 最大形态 |
|---|---|---|---|
| **Orchestration** | 派生/协调子代理 | Aider：无（单代理 by design） | Claude Code：递归组合；Omnigen：跨厂商元层 |
| **Context** | 历史/检索/压缩 | 简单消息窗口 | 层级记忆 + 自动压缩 |
| **Tool** | 文件/编辑/执行/搜索 | 少量内置 | 大型工具集 + 插件 |
| **Safety** | 权限/沙箱/审计 | 无 | 审批流 + 隔离 + 审计 |
| **Extensibility** | 用户生态加能力 | 结构类型（Python protocol） | 一切皆扩展运行时（Codex 插件市场） |

## 三个样本的定位差异

1. **Claude Code**：生产级编码 harness 标杆——recursive composition（子代理递归）、MCP 生态、安全确认、终端 UX；"应用即 harness"的完整形态。
2. **OpenAI Codex**：云 IDE 内 agent——代码沙箱 + 插件市场分发能力（marketplace-distributed plugins）；"harness + 平台分发"。
3. **Aider**：刻意最小——单代理、只做"AI 结对编程"（读文件/改文件/提交），展示"约束范围也是设计决策"。

## 与 AgentScope 对照

- 场景：这 11 个系统都是**编码专用** harness；AgentScope 是通用 harness（可承载编码/客服/研究）
- 编排：Claude Code 递归组合 ≈ AgentScope 团队工具+子代理模板
- 工具：编码工具（读/写/编辑/搜索/执行）AgentScope 内置齐全（Bash/Read/Write/Edit/Grep/Glob）
- 迁移点：编码 harness 的"工具即文件操作"与"验证即测试/编译"设计，可直接复用到 AgentScope 编码智能体
