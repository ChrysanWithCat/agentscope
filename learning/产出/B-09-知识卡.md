# B-09 多智能体编排模式

- **一句话结论**：多智能体编排是 harness 的 Subagent/Orchestration 维度，主流有四种拓扑——**交接链（handoff）、群聊（group chat）、团队（Leader-Worker）、流水线/SOP**；选择依据是"任务可分解性 × 智能体间依赖结构"。

## 四种编排拓扑

| 拓扑 | 结构 | 协调机制 | 适用 | 代表 |
|---|---|---|---|---|
| **Handoff 交接链** | A 完成→把控制权交给 B | 显式交接（会话状态移交） | 单线任务、角色接力 | OpenAI Agents SDK（核心机制）、AgentScope 无内置但可自组 |
| **Group Chat 群聊** | 多智能体共享会话轮流发言 | 发言调度 + 终止条件 | 头脑风暴、辩论、多视角 | AutoGen/AG2（GroupChat）、CrewAI 早期 |
| **Team 团队** | Leader 派生 Worker、分配任务、汇总 | 任务规划 + 工具（委派/汇报） | 复杂任务分层拆解 | AgentScope 团队工具、OpenAI "handoffs" 团队 |
| **Pipeline/SOP 流水线** | 固定步骤链，智能体按序执行 | 固化逻辑/状态机/验证 | 流程确定、需审计 | AgentScope GoalPipeline、SOPEngine、Haystack/CrewAI Flows、LangGraph 图 |

## 关键设计决策（五维的 Subagent Architecture）

1. **有无子代理**：单代理（Aider 类）vs 递归组合（Claude Code）vs 跨厂商协调（Omnigen）
2. **创建方式**：静态配置 / 运行时按需派生（AgentScope AgentCreate）
3. **层级深度**：扁平（群聊）/ 两级（Leader-Worker）/ 递归（子代理再派子代理）
4. **通信关系**：共享内存（群聊）/ 消息传递（交接）/ 工具调用（委派+汇报）

## 何时该多智能体？（关键判断，避免过度设计）

- **该**：任务天然可分（研究→写码→测试）、需要多角色视角、需要并行加速
- **不该**：单智能体 + 工具循环即可完成——多智能体引入协调开销、上下文割裂、错误传播
- **行业 2026 观察**：从"炫技式多智能体"转向"按需单智能体 + 必要时委派"；Claude Code 的 recursive composition 是主流生产形态。

## 与 AgentScope 的对照（迁移点）

- 团队：`app/_tool/` 的 TeamCreate/TeamSay/TeamDelete、AgentCreate/AgentInvite + `TeamMemberMiddleware`
- 流水线：`pipeline/_goal_pipeline.py`（面向目标执行）
- SOP：`sop/_engine.py`（结构化步骤 + 验证）
- 协议：`A2AAgent`（跨厂商智能体互操作）
- 对比：AgentScope 的编排是"自由循环 + 可选流水线"，LangGraph 是"显式图"（任何拓扑都画得出来但要求先设计），CrewAI 是"角色即抽象"
