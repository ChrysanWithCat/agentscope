# C-05 PydanticAI

- **一句话结论**：PydanticAI 把"**类型安全**"带进 harness——所有 I/O 经过 pydantic 结构化校验、依赖注入（Dependency Injection）显式声明、结构化输出为一等公民，并原生提供 **Harness 与 Graph** 两种编排形态；适合对"确定性输出"要求高的 Python 应用。

## 六元组速览

| 维度 | 答案 |
|---|---|
| L 循环 | 单代理循环（agent.run）；Graph（类 LangGraph 的状态图）作为升级路径 |
| I_act | `@agent.tool` / `@agent.tool_plain` 装饰器；工具参数经 pydantic 校验 |
| C 上下文 | 消息历史 + **动态注入**（dependency injection 把任意数据注进 prompt） |
| S 状态 | 会话级（in-memory 为主） |
| V 验证 | **类型安全是核心**：输入/输出/工具参数全结构化校验，失败即抛 |
| 多智能体 | 多 agent 组合；Tool approval gates（HITL 工具审批） |

## 核心机制（3 条）

1. **Type-safe 贯穿全链路**：模型输出先过 pydantic 校验再进业务代码；结构化输出是"保证"而非"尝试"（对比裸 JSON 解析 + json_repair）。
2. **依赖注入**：`DepsT` 泛型显式声明 agent 的外部依赖（DB 连接、服务对象），避免闭包/全局状态——可测试性极强。
3. **Harness 与 Graph**：2026 起 PydanticAI 也使用 harness 术语（单代理 harness）+ Graph（多步状态图）——说明行业术语收敛到"harness"。

## 与 AgentScope 对照

- 结构化输出：PydanticAI 原生保证；AgentScope 用 `_GenerateStructuredOutput` 工具 + StructuredResponse（机制类似，注入点不同）
- 校验：PydanticAI 全链路 pydantic；AgentScope 依赖 pydantic（模型本身是 BaseModel）但校验点分散
- 适用：PydanticAI 适合"输出必须进数据库/下游 API"的场景；AgentScope 适合"自由发挥 + 工具密集"的场景
