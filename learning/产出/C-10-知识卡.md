# C-10 LlamaIndex

- **一句话结论**：LlamaIndex 从 RAG 框架演进为 agent 框架——核心抽象是 **Workflows（事件驱动图）与 AgentWorkflow（agent 化的工作流）**，工具与检索（RAG）深度绑定；适合"以知识/文档为中心"的 agent 应用。

## 六元组速览

| 维度 | 答案 |
|---|---|
| L 循环 | **Workflows**：事件驱动图（事件→步骤→事件）；AgentWorkflow 在其上跑 agent 循环 |
| I_act | 工具（function tools + QueryEngine 工具）；与检索能力（RAG）天然集成 |
| C 上下文 | **检索是一等公民**：索引（Index）→ 检索器 → 工具/上下文注入；从 RAG 基因长出 agent |
| S 状态 | Workflow 状态（事件驱动上下文） |
| V 验证 | 事件流可观测；工具校验 |
| 多智能体 | 多 agent 工作流（agent 间经事件/工具协作） |

## 核心机制（3 条）

1. **RAG→Agent 演进路径**：LlamaIndex 的杀手锏是"把文档变成可检索资产，再让 agent 使用"——工具集里直接内置 QueryEngine（"问我的文档"）。
2. **Workflows = 事件驱动编排**：`Workflow` 定义步骤（@step）与事件流，显式但比 LangGraph 更轻（事件驱动 vs 状态图）。
3. **工具生态绑定数据**：每个检索器/索引都可包装成工具 → agent 的工具即"知识访问入口"——与 AgentScope 的 RAGMiddleware 定位互补（一个工具化、一个上下文化）。

## 与 AgentScope 对照

- RAG 接入：LlamaIndex 用"检索即工具"（agent 决定何时检索）；AgentScope 用 RAGMiddleware（循环内自动注入）
- 编排：LlamaIndex Workflows 事件驱动（显式）；AgentScope 自由循环（隐式）
- 定位：LlamaIndex 知识中心；AgentScope 任务中心——可互相借鉴（AgentScope 的 KnowledgeBase ≈ LlamaIndex 的索引+检索器）
