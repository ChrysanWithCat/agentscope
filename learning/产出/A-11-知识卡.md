# A-11 心智模型提取：AgentScope 映射到 Harness 六元组与五维

- **一句话结论**：AgentScope 不是"一个框架"，而是 **harness 设计空间的完整参考答案**——把项目映射到通用模型（H=⟨I_obs,C,L,I_act,S,V⟩ 与五维架构）后，任何其他 harness 都只是"同一组问题的不同答案"，这是三天掌握 80% harness 的迁移底座。

## 六元组映射（H = ⟨I_obs, C, L, I_act, S, V⟩，arXiv 2606.20683）

| 元组 | 含义 | AgentScope 对应 |
|---|---|---|
| **I_obs** 观察输入 | 环境反馈如何进入模型 | `ToolResultBlock`（工具结果回写上下文）、`UserMsg`、渠道消息、`_handle_incoming_event`（HITL 恢复） |
| **C** 上下文组装 | 历史/约束/检索如何拼装 | `_prepare_model_input`（3233）、`compress_context`、`_inject_runtime_state`、`ContextConfig`、RAG/记忆中间件 |
| **L** 控制循环 | 何时推理/行动/停止/重试 | `_reply_impl` 主循环 + `_next_action` 状态机（Reasoning/Acting/Exit）、`ReActConfig.max_iters`、HITL 暂停恢复、模型回退 |
| **I_act** 动作接口 | 模型输出如何变成可执行操作 | `Toolkit`（FunctionTool/MCPTool/Skill）、`_execute_tool_call`、内置 Bash/文件工具、`ToolChoice` |
| **S** 状态持久化 | 状态/会话如何保存恢复 | `AgentState`/`ReplyContext`（进程内）、服务层 `Storage`（Redis/SQL 跨会话）、`Offloader` |
| **V** 验证 | 失败检测/治理/恢复 | `FinishedReason`、`ToolResultState`（SUCCESS/ERROR/INTERRUPTED）、工具重试提示注入、`stop_on_reject`、压缩失败回退截断 |

## 五维架构映射（arXiv 2604.18071）

| 维度 | AgentScope 实现 | 设计决策点（对照用） |
|---|---|---|
| **Subagent Architecture** | 服务层团队工具（TeamSay/AgentCreate）、`A2AAgent`、SOP/GoalPipeline | 是否有子代理、层级深度、通信方式 |
| **Context Management** | ContextConfig（压缩/截断/卸载）、RAG、记忆中间件 | 存储后端、压缩策略、持久化范围、token 感知 |
| **Tool System** | Toolkit 注册制 + MCP + Skill + ToolChoice | 注册方式、扩展机制、执行路径、协议集成 |
| **Safety Mechanisms** | PermissionEngine（ALLOW/REJECT/REQUIRE_CONFIRM）+ 沙箱工作空间 | 审批流、隔离级别、审计可见性 |
| **Orchestration** | 自由 ReAct（_next_action）+ 中间件钩子链 | 控制流风格（命令式 vs 事件驱动）、规划策略 |

## 迁移方法（怎么用它学别的 harness）

每学一个新框架，问同一组 6 个问题：
1. 它的 I_obs 是什么？（工具结果如何回模型）
2. 它的 C 怎么组装？（显式/隐式上下文、是否自动压缩）
3. 它的 L 是什么循环？（ReAct/图/管道/CodeAct/事件驱动）
4. 它的 I_act 用什么协议？（function call / MCP / 代码执行）
5. 它的 S 在哪一层？（内存/checkpoint/数据库）
6. 它的 V 怎么做？（停止条件、重试、人工审批）

**同一问题的不同答案 = 框架间的本质差异**。例如：AgentScope 的 L=自由循环、LangGraph 的 L=显式图、smolagents 的 I_act=代码执行、LangGraph 的 S=每节点 checkpoint。
