# B-04 Agent Loop 模式谱系

- **一句话结论**：Agent Loop 是 harness 的 L 维度，主流范式是一个**谱系**——从 ReAct（最简推理-行动）到 Plan-Execute / CodeAct / Reflexion / Plan-Execute-Verify（PEV）；每个范式本质上是"在循环里放什么信息、什么时候停"的不同答案。

## 模式谱系（按复杂度/确定性递增）

| 范式 | 循环结构 | 停止条件 | 代表实现 | 失败模式 |
|---|---|---|---|---|
| **ReAct** | 推理(Reason)→行动(Act)→观察(Observe) | 模型不再调工具 / 轮次上限 | AgentScope `_next_action`、OpenAI Agents SDK | 循环空转、过早放弃 |
| **Plan-Execute** | 先规划(Plan)出步骤清单 → 逐步执行(Execute) → 可重规划 | 计划完成 / 计划失败 | 任务工具（TaskCreate/Update）、OpenAI "planner+executor" | 计划与实际脱节 |
| **CodeAct** | 模型输出代码 → 沙箱执行 → 观测 | 任务完成判定 / 预算 | smolagents CodeAgent、OpenAI Codex、AgentScope 内置 Bash 工具 | 代码不安全、执行结果难解析 |
| **Reflexion** | 执行后**反思**（评估失败）→ 把反思注入下一轮 | 评估通过 / 轮次上限 | Reflexion 论文、自评估 harness | 反思不产生改进 |
| **PEV**（Plan-Execute-Verify） | 计划 → 执行 → **确定性验证**（linter/测试/类型检查） | 验证通过 / 失败 | "cybernetic governor" 类 harness | 验证器不完备 |

## 关键设计问题（每个范式都要回答）

1. **循环里放什么**：只放对话历史？还是任务状态？反思文本？确定性传感器读数？
2. **什么时候推进**：固定步数？模型自主决定（"tool call → 继续"）？外部信号触发？
3. **什么时候停**：无工具调用？达到计划终点？验证通过？预算耗尽？人类否决？
4. **失败怎么回流**：错误文本直接回模型（ReAct）？反思总结（Reflexion）？验证失败回规划（PEV）？

## 与 AgentScope 的对照（迁移点）

- AgentScope 的 L = **ReAct + 增强**：`_next_action` 状态机（工具状态驱动）+ 注入运行时状态 + 任务工具（Plan-Execute 特征）+ 中断/恢复 + `stop_on_reject`。
- 学习迁移：看到新框架先归类其循环范式（图/管道/自由循环/事件驱动），再对比停止条件——**停止条件决定了 agent 是"干不完"还是"停不下来"**，是生产质量的第一分水岭。
