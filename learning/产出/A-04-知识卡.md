# A-04 主循环深读（本项目心脏）

- **一句话结论**：AgentScope 的核心是 `_reply_impl` 里的一个 **ReAct 推理-行动循环**，由 `_next_action` 状态机驱动三种动作（Reasoning/Acting/Exit），直到产出最终消息或耗尽轮次——所有组件（模型/工具/中间件/权限）都是这个循环的周边件。

## 调用链（自上而下）

```
reply_stream(288) / reply(332)         对外契约：流式事件+消息 / 一次性
  └─ _reply(892)                       包裹 on_reply 中间件链；ReplyEndEvent 逃逸才退出

          ├─ Step 1  _check_incoming_event     检查输入是否匹配"等待中的事件"（HITL）

          │          （新回复：建 ReplyContext、发 ReplyStartEvent；结构化 schema 注册工具）
          ├─ Step 3  while True: 推理-行动循环

```

## `_next_action` 决策状态机（`agent/_agent.py:3492-3752`）★

```
                    ┌─ 有可执行工具调用 → Acting(tool_calls)
  Step 1 工具状态 ──┤
                    └─ 有等待中的工具调用(权限/外部执行未决) → Exit(exit_events=None)  ← 暂停等待，回复未结束
  Step 2 结构化输出 ─┬─ 已要求&已满足 → Exit(COMPLETED)  ← 正常结束
                    ├─ 已要求&未满足 → Reasoning(提示"调用结构化输出工具")；超限则强制 tool_choice
                    └─             （cur_iter≥max_iters+grace → EXCEED_MAX_ITERS）
  Step 3 终态判定 ───┬─ final_msg 存在 → Exit(COMPLETED / EXCEED_MAX_ITERS)
                    ├─ cur_iter==max_iters → Reasoning(提示"停止调用工具，直接总结作答")
                    ├─ cur_iter>max_iters → Exit(EXCEED_MAX_ITERS)
                    └─ 默认 → Reasoning()   ← 继续循环
```

**三种动作的语义**：
- `Reasoning(hint, tool_choice)`：注入提示 → 压缩上下文 → 注入运行时状态 → 调模型（产出消息或工具调用）
- `Acting(tool_calls)`：把工具调用分批（顺序/并发）→ 逐个过权限 → 执行 → 工具结果回写上下文
- `Exit(exit_msg, exit_events)`：产出最终消息 + 结束事件（COMPLETED/EXCEED_MAX_ITERS/INTERRUPTED）；`exit_events=None` 表示"HITL 暂停"而非结束

## 三个关键设计（迁移点）

1. **事件与消息双轨**：`_reply_impl` 是 AsyncGenerator，同时 yield `AgentEvent`（流式过程）和最终 `Msg`（结果）——前端订阅事件、调用方拿消息。
2. **HITL 暂停/恢复**：权限确认、外部执行、用户中断都会让循环"停车"（Exit 但不算结束），下次以事件形式恢复。
3. **中间件吞事件机制**：ReplyEndEvent 被中间件吞掉可强制再跑一轮（`_receive_reply_end` 标志 + busy-loop 保护）。
