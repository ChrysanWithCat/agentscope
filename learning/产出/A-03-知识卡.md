# A-03 入口与四份配置

- **一句话结论**：`Agent.__init__` 是所有组件的"接线图"——6 类可插拔组件 + 4 份 pydantic 配置决定了智能体的全部行为；看懂构造器就等于拿到整棵组件树的地图。

## Agent 构造的 6 类组件（`agent/_agent.py:120-170`）

| 组件 | 参数 | 作用 |
|---|---|---|
| 身份 | `name`、`system_prompt` | 标识与系统提示（运行中可被中间件追加） |
| 模型 | `model: ChatModelBase` | 唯一必需的推理引擎 |
| 工具 | `toolkit: Toolkit` | 工具/MCP/Skill 的唯一来源（缺省自动建空 Toolkit） |
| 中间件 | `middlewares: list[MiddlewareBase]` | 按 7 个钩子点分流缓存（见 A-08） |
| 状态 | `state: AgentState` | 会话/回复/工具上下文（缺省新建） |
| 卸载器 | `offloader: Offloader` | 压缩上下文/工具结果的外部存放（配合工作空间） |

构造器内部还做了三件关键事：建 `PermissionEngine`（从 state 取权限上下文）、注册内置压缩工具 `_GenerateStructuredOutput`（结构化输出用）、把中间件按钩子点分桶。

## 4 份配置（`agent/_config.py`，全部 pydantic BaseModel）

### ① ContextConfig —— 上下文管理（压缩/截断/卸载）
- `trigger_ratio=0.8`：token 超过上下文 80% 触发压缩（上限 0.9，留压缩空间）
- `reserve_ratio=0.1`：压缩时保留的 token 比例
- `context_buffer_ratio=0.2`：缓冲带——达到 60% 就提示 agent"压缩临近"
- `compression_prompt` + `summary_template` + `summary_schema`：压缩摘要由模型生成，结构化 Schema 为 **task_overview / current_state / important_discoveries / next_steps / context_to_preserve** 五段
- `tool_result_limit=50000`：工具结果超长截断；`max_image_num=5`：图片超限卸载到工作空间
- `compression_tool_enabled`：是否把压缩暴露成 agent 可主动调用的工具

### ② InjectionConfig —— 运行时状态注入（帮模型"感知当下"）
- `inject_runtime_state=True`：每次推理前注入**当前时间、任务状态、上下文占用**
- `timezone/time_format/time_interval=0.5h`：时间注入节奏
- `tool_retries_limit=3`：同一工具同参数连续失败 3 次 → 注入"别重复试"的提示
- `task_tool_names`：上下文已有任务工具调用时，抑制重复任务注入
- `extra_fields`：自定义注入字段

### ③ ReActConfig —— 推理-行动循环边界
- `max_iters=50`：一次回复最多循环轮数
- `structured_output_grace_iters=5`：超限后仍允许的"生成结构化输出"宽限轮
- `stop_on_reject=False`：工具被权限拒绝后是否停止
- `interruption_message` / `interruption_raise_cancelled_error`：中断行为

### ④ ModelConfig —— 模型容错
- `max_retries=0`：主模型失败重试次数（默认不叠加模型内部重试）
- `fallback_model`：主模型失败后的回退模型

## 配置的哲学（迁移点）

这四份配置恰好对应 harness 通用设计的四类问题：**Context（上下文管理）、Observation（注入运行时状态）、Loop（循环边界）、Resilience（模型容错）**——Day 2 的六元组模型会再次见到它们。
