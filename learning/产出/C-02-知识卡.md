# C-02 OpenAI Agents SDK

- **一句话结论**：OpenAI Agents SDK（由 Swarm 演化）是"**最简核心抽象 + handoff 交接链**"的 SDK 型 harness——只有三个核心概念（Agent、Runner、handoff），用显式交接把控制权在智能体间传递；模型无关（100+ LLM 经 LiteLLM 适配）。

## 核心抽象（只有三个）

1. **Agent**：指令（instructions）+ 工具集 + guardrails + 交接权限（handoffs）
2. **Runner**：执行 agent 循环（`agent.run()` / `run_streamed()`）
3. **Handoff**：一个 agent 把会话控制权交给另一个（`handoff(agent)`），交接可带提示

## 六元组速览

| 维度 | 答案 |
|---|---|
| L 循环 | ReAct 循环（runner 内部）；多智能体=**handoff 链**（线性接力，非并行） |
| I_act | `@function_tool` 装饰器；原生 MCP 支持（2026）；sandboxed tools |
| S 状态 | **Sessions**（会话隔离，无内置节点级 checkpointing）——重启后从会话恢复对话，不保证执行断点续跑 |
| V 验证 | **Guardrails**（输入/输出校验器，在循环外钩住） |
| C 上下文 | 会话内历史；记忆靠 session |
| 多智能体 | handoff 为主；团队（子代理委派）2026 增强 |

## 核心机制（3 条）

1. **Guardrails 是"非循环内"的护栏**：输入 guardrail 在 agent 开始前校验用户消息，输出 guardrail 在完成后校验——与 AgentScope 的权限引擎（工具执行前）定位不同。
2. **Handoff 是显式交接**：模型决定把控制权交给谁（交接权限被列入工具）；适合"角色接力"（客服→专家→结算），不适合需要并行/群聊的场景。
3. **模型无关**：OpenAI-first 但经 LiteLLM 支持 100+ 模型——生态上"用 OpenAI 体验，接任意模型"。

## 与 AgentScope 对照

- 抽象数量：SDK 只有 3 个核心概念（易上手）；AgentScope 概念更多（组件化），但自由度高
- 多智能体：OpenAI 用 handoff（线性）；AgentScope 用团队工具+流水线（可并行、可分层）
- 安全：OpenAI 用 guardrails（输入/输出校验）；AgentScope 用 PermissionEngine（工具级决策）
- 持久化：两者都在会话层（OpenAI sessions / AgentScope Storage），都无节点级 checkpoint
