# B-07 状态持久化与 Durable Execution

- **一句话结论**：State 维度回答两个问题——**"从哪恢复"（状态存了什么）和"恢复什么"（会话/任务/工具/checkpoint 的粒度）**；Durable Execution（LangGraph checkpointing 为代表）让"进程崩溃后从任意节点续跑"成为生产 harness 的分水岭能力。

## 状态的两个层次

| 层次 | 内容 | 粒度 | 代表 |
|---|---|---|---|
| **会话状态** | 对话历史、session 配置 | 消息级 | AgentScope Storage（Redis/SQL）、OpenAI Agents SDK sessions |
| **执行状态** | 节点/步骤进度、checkpoint、未完成任务 | **节点级**（可恢复） | LangGraph checkpointer；Temporal 类工作流引擎 |

## 关键设计决策（五维 Context 维度的"持久化范围"）

1. **存什么**：只存消息？消息+任务状态？消息+任务+checkpoint+中间产物？
2. **粒度**：整会话一次存 / 每轮存 / **每节点存**（checkpoint）——粒度越细越可恢复，开销越大
3. **后端**：内存（重启即失）/ Redis（跨进程）/ SQL（审计）/ 对象存储（大产物）
4. **恢复语义**：恢复后继续跑（durable）还是重放？（LangGraph 从 checkpoint 续跑 vs CrewAI 从头重跑）
5. **HITL 暂停也靠状态**：等待用户确认的"停车点"必须可持久化，否则确认后无法续（AgentScope 的 awaiting_tool_calls + 事件恢复）

## Durable Execution 的意义（迁移点）

- 无 durable：长任务跑 30 分钟，进程崩了全丢 → 只能短任务。
- 有 durable：节点级 checkpoint → 崩溃/升级/限流后从断点续跑 → 长任务可生产化。
- 这就是 LangGraph 被选为"stateful production workflows"默认的原因；OpenAI Agents SDK 有 sessions 但"no built-in checkpointing"；CrewAI 的 Flows 只有较粗的恢复。**持久化粒度 = 生产成熟度的标尺**。

## 与 AgentScope 的对照

- 进程内：`AgentState`（ReplyContext/awaiting tool calls）——支持 HITL 停车与恢复
- 跨会话：服务层 `StorageBase`（Redis/SQL）+ 10 类数据模型（Session/Agent/Team/Schedule…）
- 后台任务：`BackgroundTaskManager` + 工具 offload（ToolOffloadMiddleware）——长工具转后台，结果经总线唤醒
- 对比：AgentScope 的持久化在"会话层"，LangGraph 在"节点层"——AgentScope 的恢复单位是"一次回复的 HITL 停车点"，LangGraph 是"任意图节点"
