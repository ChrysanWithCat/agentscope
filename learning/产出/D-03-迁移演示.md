# D-03 迁移演示：用 OpenAI Agents SDK 的概念复述 AgentScope

> 目的：证明"六元组/五维统一模型"可跨框架迁移。左列是 OpenAI Agents SDK 概念，右列是 AgentScope 的对应实现（一一对应）。

## 对照表（概念迁移）

| OpenAI Agents SDK 概念 | AgentScope 对应 | 说明 |
|---|---|---|
| `Agent(instructions=...)` | `Agent(name=..., system_prompt=...)` | 智能体定义：指令/系统提示 |
| `@function_tool` 装饰器 | `FunctionTool(func, name=...)` + `Toolkit.add_tool` | 工具注册（装饰器 vs 显式注册表） |
| `Runner.run(agent, input)` | `agent.reply_stream(input)` | 执行循环入口 |
| handoffs（交接链） | `app/_tool` 团队工具 + `AgentInvite`（委派 Worker） | 多智能体控制权传递 |
| guardrails（输入/输出校验） | `PermissionEngine`（工具执行前决策）+ 中间件 `on_check_permission` | 安全护栏（位置不同：循环外 vs 工具前） |
| sessions（会话隔离） | 服务层 `Storage` Session 模型 + `AgentState` | 会话状态持久化 |
| MCP 原生支持 | `MCPTool` + `MCPClient` | 工具协议（同一 MCP 生态） |
| streaming（run_streamed） | `reply_stream` → AgentEvent 流 | 流式输出 |

## 伪代码对照（同一"带工具的客服 agent"）

**OpenAI Agents SDK 风格：**
```python
agent = Agent(
    name="Support",
    instructions="You are a support agent.",
    tools=[search_kb, create_ticket],          # @function_tool 装饰
    handoffs=[handoff(escalation_agent)],       # 交接
)
result = await Runner.run(agent, "我的订单在哪？")
```

**AgentScope 风格（概念等价）：**
```python
agent = Agent(
    name="Support",
    system_prompt="You are a support agent.",
    toolkit=Toolkit(tools=[search_kb, create_ticket]),   # FunctionTool 注册
    # 委派能力经团队工具/子代理模板，而非 handoff
)
async for evt in agent.reply_stream("我的订单在哪？"):   # 事件流
    ...
```

## 迁移结论（3 条）

1. **抽象一一对应**：instructions↔system_prompt、tools↔Toolkit、runner↔reply_stream、sessions↔Storage、guardrails↔PermissionEngine、MCP↔MCPTool——**没有"框架特有魔法"，只有命名与挂点差异**。
2. **差异集中在三处**：多智能体拓扑（handoff 线性 vs 团队/流水线）、安全挂点（循环外 vs 工具前）、状态粒度（会话级 vs 会话级+checkpoint）。
3. **迁移心法**：遇到新框架先画它的六元组（B-02），再与 AgentScope 逐元对比——80% 的知识直接复用。
