# B-03 五维架构与七层分类

- **一句话结论**：arXiv 2604.18071 从**架构决策**视角给出 harness 的五个维度（子代理 / 上下文管理 / 工具系统 / 安全机制 / 编排），ETCLOVG 七层分类（Execution/Tooling/Context/Loop/Observation/Verification/Governance）是另一个互补框架——前者问"要做什么决策"，后者问"有哪些层"。

## 五维架构（每个维度的设计决策点）

| 维度 | 要决策的问题 | 典型选项 |
|---|---|---|
| **Subagent Architecture** | 是否有子代理、创建方式、层级深度、通信关系 | 无子代理 / 按需派生 / 递归组合 / 跨厂商协调 |
| **Context Management** | 存储后端、压缩策略、持久化范围、token 感知 | 内存 / 文件持久 / 混合 / 层级；压缩 vs 截断 vs 卸载 |
| **Tool System** | 注册方式、扩展机制、执行路径、协议集成 | 注册表 / 插件 / MCP / A2A；schema 校验 |
| **Safety Mechanisms** | 审批流、隔离级别、审计可见性 | 无 / 中间隔离（沙箱+权限提示）/ 高保证审计（provenance-aware） |
| **Orchestration** | 控制流风格、规划策略、事件驱动 vs 命令式 | 自由循环 / 显式图 / 管道 / 流水线 / 事件驱动 |

## ETCLOVG 七层分类（Structural Pillars + Control Plane）

**四根结构支柱**：
- **E Execution**：代码运行器、浏览器、文件系统、沙箱——模型周围的执行环境
- **T Tooling**：工具协议（MCP、A2A）、工具定义、动作空间管理、schema 验证
- **C Context**：上下文窗口管理、压缩、检索、缓存、技能注入
- **L Loop**：循环调度（ReAct 变体、planning、停止条件）

**三层控制面**：
- **O Observation**：环境信号采集与格式化
- **V Verification**：确定性校验（linter/测试/类型检查）与失败检测
- **G Governance**：审计、权限、护栏、策略

## 两个框架的关系（迁移点）

- 五维 = **决策视角**（架构师问"选哪个选项"）
- 七层 = **结构视角**（工程师问"哪一层放什么"）
- 六元组（B-02）= **运行时视角**（调试者问"数据流经哪里"）
- 三个框架都指向同一现实：**harness 是可枚举的设计空间，不是玄学**。学框架时把它们当"填空模板"：每个维度/层的 AgentScope 答案 = A-11 的映射。
