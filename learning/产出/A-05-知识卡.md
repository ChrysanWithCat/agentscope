# A-05 消息、事件、状态三件套

- **一句话结论**：AgentScope 用三类数据对象贯穿整个循环——**Msg（消息，进模型上下文）**、**AgentEvent（事件，流式输出给前端）**、**AgentState（状态，驱动决策）**；三者是"内容、过程、控制"的分工。

## ① 消息体系（`message/`）

**Msg 结构**（pydantic BaseModel，`message/_base.py:70`）：
- `name`：发送者标识
- `content: list[ContentBlock]`：内容块列表（多模态的核心）
- `id`/`timestamp`/`role`（user/assistant/system/broadcast）/`finished_reason`/`usage`

**ContentBlock 协议**（`message/_block.py`）—— 内容就是"块的列表"：
| 块 | 含义 |
|---|---|
| `TextBlock` | 文本 |
| `ThinkingBlock` | 模型思考过程 |
| `HintBlock` | 系统注入提示（带 `source` 标记，用于识别自己的注入） |
| `ToolCallBlock` | 工具调用（`state: PENDING/ALLOWED/DONE/INTERRUPTED`） |
| `ToolResultBlock` | 工具结果（`state: SUCCESS/ERROR/INTERRUPTED`，`done` 标志） |
| `DataBlock` | 多模态数据（`Base64Source` / `URLSource`：图像/音频） |

**角色消息**：`UserMsg`（只能 text+data）、`AssistantMsg`（可含 tool_call 块）、`SystemMsg`（只能 text）——构造时有断言校验。

## ② 事件系统（`event/_event.py`，30+ 事件）

一次带工具调用的回复典型事件序列：
```
ReplyStart → ModelCallStart → Text/Thinking/Data 块事件 → ModelCallEnd
→ ToolCallStart → ToolResultStart → ToolResultTextDelta → ToolResultEnd → ToolCallEnd
→ （再次 Reasoning 则重复）→ ReplyEnd(COMPLETED/EXCEED_MAX_ITERS/INTERRUPTED)
```
分类：回复生命周期（ReplyStart/End）、模型调用（ModelCall*）、内容块（Text/Data/Thinking/Hint）、工具（ToolCall*/ToolResult*）、**HITL**（RequireUserConfirm/UserConfirmResult/UserInterrupt/ExternalExecution*）、Custom。

## ③ 状态体系（`state/_state.py`）

- `AgentState`（BaseModel）：`reply_context`、`permission_context`、消息历史上下文；方法 `append_context`、`has/get_awaiting_tool_calls`、`get_unfinished_tool_calls`、`reply_id`/`cur_iter` 属性
- `ReplyContext`：`reply_id`、`cur_iter`、`structured_schema`、`structured_output` —— **主循环的"方向盘"**
- `TaskContext` / `Task`：任务状态（配合 TaskCreate/Update 工具）
- `ToolContext`：工具运行上下文（含文件缓存 ReadCacheEntry）

## 三者的分工（迁移点）

- **Msg** = 模型的输入输出（内容层）
- **AgentEvent** = 给外部看的流（过程层，前端订阅）
- **AgentState** = 内部决策依据（控制层，`_next_action` 只读它）
- 对应 harness 六元组：Msg→C（上下文），Event→I_obs/V（观测与验证反馈），State→S（状态持久化）。
