## 一、项目全景

### 1.1 是什么

AgentScope 2.0 是阿里巴巴通义实验室 SysML 团队开源的生产级智能体框架（Apache-2.0，Python ≥ 3.11）。它的设计哲学是：**发挥大模型推理与工具调用能力，而非用严格提示词和固化编排束缚模型**。核心抽象围绕一个"自由推理-行动循环"（ReAct）展开。

两大层级：

| 层级 | 定位 | 入口 |
|---|---|---|
| **Agent SDK**（`src/agentscope/agent`、`message`、`model`、`tool`…） | 用构建模块组合出单个/多个智能体 | `agentscope.agent.Agent` |
| **Agent Service**（`src/agentscope/app`） | 把智能体变成多租户、多会话、多渠道的应用 | `agentscope.app.create_app`（FastAPI） |

### 1.2 仓库布局

```
agentscope/
├── src/agentscope/        # 全部源码（478 个 .py）
├── examples/              # 端到端示例（a2a/agent_service/console/rag/realtime/tui/workspace/…）
├── docs/                  # NEWS_zh.md（功能演进）、roadmap.md、changelog.md
├── tests/                 # 测试
├── scripts/               # 脚本
├── learning/              # 学习材料（diagram.md 架构图、本文档）
└── pyproject.toml         # 依赖与 extras（模型/服务/存储/渠道/沙箱/记忆等可选依赖）
```

### 1.3 版本与依赖要点（pyproject.toml）

- Python ≥ 3.11；核心依赖：openai、anthropic、dashscope、mcp、httpx、opentelemetry、rich、aiofiles 等。
- 按需安装的 extras：`[models]`、`[service]`（fastapi/uvicorn/apscheduler/ag-ui-protocol）、`[storage-sql/redis/s3]`、`[channel]`（飞书/discord/钉钉）、`[workspace]`（docker/e2b/daytona/k8s/opensandbox）、`[memory]`（mem0/reme）、`[rag]`+`[vdb-*]`、`[realtime]`、`[tui]`、`[a2a]`、`[full]`。
- **学习建议**：第一梯队只装核心 + `[service]`；用到哪个扩展再装对应 extra。

## 二、入口点导航（从入口点驱动）

系统只有两个真正的入口，学习时从这里出发向内部追：

### 入口 1：SDK 入口 —— `Agent`

```
src/agentscope/agent/_agent.py
├── class Agent                         # 智能体主类
│   ├── __init__(name, system_prompt, model, toolkit, middlewares,
│   │            state, offloader, model_config, context_config,
│   │            react_config, injection_config)
│   ├── reply_stream(msgs, structured_schema=None)   # 流式回复（事件+消息）
│   ├── reply(msgs, structured_schema=None)          # 一次性回复
│   ├── observe(msgs)                                # 只观察不回复
│   └── compress_context()                           # 上下文压缩（由中间件/内置工具触发）
```

驱动路径：`Agent` 构造时接收 6 类可插拔组件（模型 / 工具集 / 中间件 / 状态 / 卸载器 / 4 份配置），`reply*` 是唯一对外出口。**读懂 `__init__` 等于拿到整棵组件树的地图**。

### 入口 2：服务入口 —— `create_app`

```
src/agentscope/app/_app.py
└── create_app(storage, message_bus, workspace_manager,
               knowledge_base_manager, mcp_hubs, skill_hubs,
               channels, custom_subagent_templates, ...) -> FastAPI
```

驱动路径：`create_app` 把**存储**、**消息总线**、**工作空间管理**三件必需件 + 可选件（知识库、Hub、渠道、团队模板）组装成一个 FastAPI 应用；内置 14 组路由（`app/_router/`），由 `app/_service/` 执行业务逻辑，`app/_manager/` 跑调度与后台任务。

### 两个入口的关系

```
服务入口 create_app ──(每次会话/每次消息)──> 实例化/唤醒 ──> SDK 入口 Agent ──> 推理-行动循环
```

服务层不重复实现智能体逻辑，而是**按用户/会话/Agent 编排实例，把 SDK 的 Agent 跑起来**。先学 SDK 入口，再学服务入口，路径是单向收敛的。

## 三、端到端请求路径

### 3.1 路径 A：SDK 单 Agent 的一次回复（核心路径，必走）

一次 `agent.reply(...)` 的完整调用链（沿 `_agent.py` 自上而下）：

```
用户消息 Msg
  │
  ▼
Agent.reply_stream / reply                        (_agent.py:288 / 332)
  │  （经过 on_reply 中间件链）
  ▼
_reply                                              (_agent.py:892)
  │  （on_reply 中间件包裹；等待 ReplyEndEvent 逃逸才退出）
  ▼
_reply_impl                                         (_agent.py:1027) ★主循环
  │
  ├─ Step 1  _check_incoming_event                  检查输入是否匹配"等待中的事件"
  ├─ Step 2  _handle_incoming_event /              处理 HITL 事件 / 或
  │          _handle_incoming_messages             接收新消息、建 ReplyContext、发 ReplyStartEvent
  ├─ Step 3  while True: 推理-行动循环
  │     │
  │     ├─ _next_action(final_msg)                  (_agent.py:3492) ★决策点
  │     │     └─ 返回 Reasoning(hint, tool_choice) / Acting(tool_calls) / Exit(...)
  │     │
  │     ├─ case Reasoning:
  │     │     ├─ compress_context()                 上下文压缩（若需要）
  │     │     ├─ _inject_runtime_state()            注入时间/任务/上下文占用
  │     │     └─ _reasoning(tool_choice)            (_agent.py:1633) 推理阶段
  │     │           └─ _reasoning_impl → _call_model → 模型调用链
  │     │                 （on_model_call 中间件 → 厂商 ChatModel → 流式 Token/事件）
  │     │
  │     └─ case Acting:
  │           ├─ _batch_tool_calls(tool_calls)      批处理编排（顺序/并发）
  │           ├─ _check_permission(tool_call)       (_agent.py:2332) 权限引擎
  │           │     └─ _check_permission_impl → PermissionEngine
  │           └─ _execute_tool_call(tool_call)      (_agent.py:2423) 行动阶段
  │                 ├─ Toolkit 查找已注册工具（FunctionTool / MCPTool / Skill）
  │                 ├─ 执行 → ToolResult → 回写上下文
  │                 └─ 可能触发 RequireUserConfirmEvent（HITL 暂停）
  │
  └─ 循环结束条件：Exit 且 ReplyEndEvent 未被中间件吞掉 / cur_iter ≥ max_iters
  │
  ▼
最终 AssistantMsg + ReplyEndEvent（事件流逐段 yield 给调用方）
```

**关键阅读顺序**（`agent/_agent.py` 内）：
1. `__init__`（117-245）——组件接线
2. `reply` / `reply_stream`（288-380）——对外契约
3. `_reply_impl`（1027-1296）——主循环骨架（先把 case 分支看懂）
4. `_next_action`（3492 起）——循环的决策状态机（Reasoning/Acting/Exit）
5. `_reasoning_impl`（1690 起）、`_acting_impl`（2765 起）、`_execute_tool_call`（2423 起）——两大阶段细节
6. `_call_model`（3271 起）——模型调用与中间件链
7. `_check_permission`（2332 起）——权限检查链

### 3.2 路径 B：Agent Service 的一次聊天请求

```
HTTP POST /chat（或 IM 渠道消息）
  │
  ▼
FastAPI 路由 app/_router/_chat.py  → chat()（流式 SSE / 轮询）
  │
  ▼
app/_service/_chat.py  ChatService
  ├─ run()                    创建/唤醒会话 → 构建 Agent 实例（按用户+Agent+会话）
  ├─ _run_impl()              挂载 app 层中间件（Inbox/StateChange/TeamMember/ToolOffload）
  ├─ Agent.reply_stream(...)  进入路径 A
  ├─ _persist()               把消息/状态写入 Storage（Redis/SQL）
  └─ _project_event()         把 AgentEvent 投影为 AGUI 协议事件 → 推给前端/渠道
  │
  ▼
WebSocket / SSE / IM 渠道  →  Web UI（examples/web_ui）
```

对应阅读：`app/_router/_chat.py` → `app/_service/_chat.py` → `app/middleware/_protocol/_agui.py`（AGUI 协议）→ `app/storage/_base.py` → `app/message_bus/_base.py`。

### 3.3 路径 C：终端调试路径（Console / TUI）

```
launch_console(agent)     examples/console        # 终端对话：流式输出+工具确认+Ctrl+C
launch_tui(agent)         src/agentscope/tui      # 富文本 TUI（ChatUI/MessagesUI/Realtime）
```

适合在学习初期**不写 Web 代码就能交互调试**，强烈建议阶段 1 就用它跑通。

## 五、学习规划（分阶段）

> 时间按**全职**估算；业余学习者请把"天"换算成"周内 2-3 个晚上"。每个阶段都有**验收标准**，达标再进入下一阶段。官方文档章节链接：https://docs.agentscope.io/latest/zh/

### 阶段 0：环境与总览（0.5 天）

**目标**：装好环境，看懂地图。
- 安装：`uv pip install -e ".[full]"`（或先只装核心，边学边补）
- 通读：`README_zh.md`、`learning/diagram.md`（架构图）、`docs/NEWS_zh.md`（功能演进史）
- 确认至少一家模型 API Key（推荐 DashScope 或 OpenAI）
- 验收：能解释"SDK 层 vs 服务层"的区别；能指出 6 个核心子包的位置。

### 阶段 1：入口与端到端路径（1-2 天）

**目标**：从入口出发，走通一次完整回复。
- 必读：`examples/console/`（跑通终端对话）、`src/agentscope/agent/_agent.py` 的 `__init__` + `reply` + `reply_stream`
- 必做：
  1. 用 `Agent` + `Toolkit`（Bash/Grep/Read/Write）+ `launch_console` 写一个可对话智能体
  2. 用调试器在 `_reply_impl` 的 Step 3 打断点，观察 Reasoning/Acting/Exit 三种动作交替
  3. 手绘一张"入口 → 主循环 → 模型/工具 → 输出"的调用链图（对照第 3.1 节）
- 验收：能不看文档讲出 `reply()` 从进入 `_reply_impl` 到返回 `AssistantMsg` 经过了哪 5 个关键方法。

### 阶段 2：核心闭环深读——消息、事件、状态（2-3 天）

**目标**：吃透数据在循环里如何流转。
- 必读：`message/_base.py`、`message/_block.py`、`event/_event.py`、`state/_state.py`、`state/_task.py`
- 必做：
  1. 写脚本构造 `UserMsg`（含文本+图片 DataBlock），走 `reply_stream` 打印所有事件类型
  2. 对照 `event/_event.py` 整理"一次带工具调用的回复"会依次发出哪些事件（ReplyStart → ModelCall → ToolCall → ToolResult → ReplyEnd）
  3. 阅读 `_next_action` 的决策逻辑（`agent/_agent.py:3492`），画出 Exit 的三种情形
- 验收：能回答"事件流和消息流为什么是两条轨道"；能说明 `ReplyContext` 的字段含义。

### 阶段 3：组件扩展——模型、工具、中间件、权限（4-5 天）

**目标**：理解四个可插拔组件如何接入循环。
- 必读（按序）：
  1. `model/_base.py` + 任一家实现（如 `model/_openai_chat.py`）+ `model/_model_response.py`
  2. `credential/_base.py` + `credential/_factory.py`
  3. `formatter/_formatter_base.py` + `formatter/_openai_formatter.py`（对比各家 formatter）
  4. `tool/_toolkit.py`、`tool/_base.py`、`tool/_builtin/_backend.py`、`tool/_task/`
  5. `middleware/_base.py` + `middleware/_budget.py`（最小实现范例）+ `middleware/_model_router.py`
  6. `permission/_engine.py`、`permission/_rule.py`
- 必做：
  1. 用 `FunctionTool` 注册 2 个自定义工具（一个同步、一个 `is_concurrency_safe=False`）
  2. 写一个自定义中间件实现 `on_model_call`（打印/改写请求）并挂到 Agent 上
  3. 配置 `PermissionRule`：让某个工具先 `REQUIRE_CONFIRM`，在 Console 里走一次 HITL 确认
  4. 给 Agent 配置 `ModelConfig(fallback_model=...)`，人为让主模型报错观察回退
- 验收：能独立写一个"带 3 个工具 + 权限确认 + 预算中间件"的 Agent；能讲清 7 个中间件钩子的触发时机。

### 阶段 4：扩展构建模块（4-5 天，按需裁剪）

**目标**：把核心能力接到知识、记忆、沙箱、语音等真实场景。
- 路线 A（知识增强）：`rag/_knowledge.py` → `rag/_parser/` → `rag/_vdb/` → `embedding/` → `middleware/_rag.py`，跑通 `examples/rag`
- 路线 B（记忆）：`middleware/_longterm_memory/`（Agentic Memory → Mem0 → ReMe），跑通 `examples/long_term_memory/`
- 路线 C（代码执行）：`workspace/_base.py` + `workspace/_docker.py` + `tool/_builtin/_backend.py`，跑通 `examples/workspace`
- 路线 D（协议互通）：`mcp/_mcp_client.py` + `skill/_local_loader.py` + `tool/_adapters.py`（MCPTool/FunctionTool）
- 路线 E（编排）：`sop/_engine.py` + `pipeline/_goal_pipeline.py`，跑通 `examples/pipeline/goal`
- 路线 F（语音/实时）：`realtime/` + `agent/_realtime/` + `tts/`，跑通 `examples/realtime`
- 验收：至少完整走通 2 条路线，并在阶段 3 的 Agent 上组合出"RAG + 记忆 + Docker 沙箱"的增强智能体。

### 阶段 5：服务层（5-7 天）

**目标**：把 Agent 变成多租户应用。
- 必读（按序）：
  1. `app/_app.py`（create_app 全部参数）
  2. `app/storage/_base.py` + `app/storage/_redis_storage.py`（或 `_sql_storage.py`）
  3. `app/message_bus/_base.py`
  4. `app/_router/_chat.py` + `app/_service/_chat.py`（ChatService 全流程）
  5. `app/middleware/_inbox_middleware.py` + `app/middleware/_protocol/_agui.py`
  6. `app/_manager/_scheduler/_scheduler_manager.py`（调度）
  7. `app/channel/_base.py` + 一个渠道（如 `app/channel/_feishu/_channel.py`）
- 必做：
  1. 仿照 `examples/agent_service/main.py` 起一个本地服务（Redis 可用内存版替代），curl 调一次 `/chat`
  2. 用 WebSocket 消费流式事件，观察 AGUI 事件结构
  3. 创建一个定时任务（schedule 工具），验证到点唤醒 Agent
  4. 配置 `custom_subagent_templates`，让 Leader 派生 Worker（`app/_tool/_team_say.py`）
- 验收：能讲清"一次聊天请求从 HTTP 到 Agent 再到存储"的完整链路（对照 3.2 节）；能说出 storage / message_bus / workspace_manager 三个必需件的职责边界。

### 阶段 6：综合实战（持续 1-2 周）

**目标**：从"读懂"到"能改、能造"。
- 建议项目（任选）：
  1. **复刻**：基于 `examples/agent_service` 做一个垂直场景服务（客服/资料问答/代码助手），接入一个 IM 渠道
  2. **扩展**：写一个新厂商的 `ChatModel` + `Formatter` + `Credential`（对照 `model/_deepseek/` 全套模式）
  3. **改造**：写一个新中间件（如日志审计、敏感词拦截），挂到服务层 `extra_agent_middlewares`
  4. **研究**：精读 `_next_action` 与 `react_config`，实验不同 `max_iters`/工具并发策略对效果的影响
- 验收：交付一个可运行、有测试（可参考 `tests/`）、有文档的小项目；对改造点能指出改动前后源码中的对应位置。
